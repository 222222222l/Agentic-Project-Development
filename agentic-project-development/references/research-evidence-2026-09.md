## 调研范围与证据门槛

检索窗口为 **2026-07-05 至 2026-09-05**，按 arXiv 提交历史确认日期，
分别记录首次提交和所读版本。覆盖 coding agent、工具接口、上下文、技能迁移、
长程执行、失败恢复、协作和 harness 优化；这是面向开发效能的定向调研，
不声称穷尽所有 agent 论文。检索词包括 coding agent efficiency、tool architecture、
skill transfer、harness verification、long-horizon、context files、multi-agent coordination。
搜索摘要仅用于发现，结论以链接的一手论文为准。

证据分为：**受控实验**、**基准诊断**、**观察/经验报告**。
多数新增来源是预印本；论文声称的收益不等于本 skill 的复现收益。
只有对照、消融或跨配置证据支持、且能保持适用边界的方法才转化为指导。
训练所得能力、单一模型结果、理论假设和特定框架不可直接变成通用提示词规则。

## 可吸收的实证结果

### 1. 工具组合与检索

- **[The Devil Is in the Interface](https://arxiv.org/html/2608.11386v1)**，
  2026-08-11，v1；§2.2、§3、附录 B。受控实验：65 个 SWE-bench Live 问题、
  3 个 actor、6 种工具架构、每题 10 次，共 11,700 条轨迹。Python 接口在总体
  成功表现相近时减少 41.6% 步骤、56.3% token；结构化原子工具改善重复可靠性。
  吸收：利用现有工具做批量读取和程序化结果处理，保持逐项结果可检查。
  边界：这不是所有工具都应改成 Python 的证明；自然语言搜索也增加噪声。
- **[When Does Restricting a Coding Agent to execute_code Help?](https://arxiv.org/abs/2607.10569v1)**，
  2026-07-12，v1。两个 agent、两类任务、三种工具面交叉对照；四个配置单元中
  三个成本更低或统计上持平，Claude 的 SWE-bench 单元方向相反且不显著。
  吸收：在实际模型、缓存计费和任务上比较工具面；保留原生编辑/终端能力。
  不把“未显著差异”写成已证明等效，也不将 CLI/MCP 作普遍优劣排序。
- **[CodeGrep](https://arxiv.org/abs/2608.05886v1)**，2026-08-06，v1。
  在 500 个 SWE-bench Verified 问题上，训练过的 14B 检索器配合固定 30B agent，
  解题率 27.0% 对 25.8%；成功实例少用 15% 轮次、19% token。
  吸收：检索结果要提供精确位置、相关理由及遗漏边界，按下游解题成本评估。
  边界：成功实例成本存在条件化选择；训练收益和 0.677 精确率不能照搬为路由阈值。

### 2. 验证预算与失败诊断

- **[HarnessLens](https://arxiv.org/html/2608.27311v1)**，2026-08-27，v1；
  §4.3、表 1、§6。三个 harness（OpenCode、Codex CLI、Pi）、四个基准，
  固定 deepseek-v4-flash-preview。平均 held-out pass@1 分别从
  41.83→47.53、40.94→44.06、45.49→49.67：**+5.70/+3.12/+4.18 个百分点**，
  摘要的 7.6–13.6% 是相对改善。吸收：按改动行为挑选开发测试，加回归哨兵，
  确认改动确实被执行，再用未用过的开发任务确认，最终保留封存评测。
  边界：仅一个基础模型，基线预算口径不同，部分 coding 单元无提升。
- **[SkillHEX](https://arxiv.org/html/2608.05628v1)**，2026-08-06，v1；表 1–2。
  87 个 SkillsBench 任务、两个模型、三个 seeds、五轮任务内适配；均值为
  55.9%/57.9%。移除自验证使 GPT-5.3-Codex 结果下降 11.1 个百分点，
  移除分支保留下降 6.8 个百分点。吸收：先提出可证伪原因，用廉价测试区分，
  保留有效候选与失败记录。边界：自生成测试仅用于诊断，不代替外部验收；
  任务内修复不证明跨任务迁移，完整树搜索仍需预算和本地收益证据。
- **[AgentTether](https://arxiv.org/abs/2607.06273v1)**，2026-07-07，v1。
  261 个 τ-bench 任务；Banking 上修复 Qwen 的 49/83 和 GPT 的 56/86 个
  初始失败任务。保留已有的依赖定位、局部修复和适用域内修复记忆。
  边界：分母是初始失败子集，不能称为整体成功率提升 59%/65%。
- **[HarnessOpt-Bench](https://arxiv.org/abs/2608.06301v1)**，2026-08-06，v1。
  五个优化模型、四项下游任务、111 次计分运行；原生 harness 不总占优。
  吸收其评测边界：隔离不可见测试分区、计入优化预算、保留候选版本。
  这是测量协议与差异证据，不是某个优化器的通用优胜证明。

### 3. 上下文与技能粒度

- **[Break It Down, Pass It On](https://arxiv.org/html/2608.20274v1)**，
  2026-08-20，v1；§4–6、附录 E。11 个模型，AppWorld 417、OfficeBench 300、
  KramaBench 92 个任务；分别对照各自无记忆基线。子任务级技能平均更能迁移，
  文本格式总体优于整任务代码经验。吸收：提炼带触发条件和验证方式的小型程序知识。
  边界：不是仓库修复实验证明，不应删除已验证的确定性脚本；utility 分数不能代替运行。
- **[Do Context Files Help Coding Agents?](https://arxiv.org/html/2607.27250v1)**，
  2026-07-28，v1；§4.5–6、Limitations。两个 agent、三个 Python 仓库、
  17 个任务、288 个有有效评分的运行；未检出正确性改善。
  吸收：优先写影响行为的命令、约束、测试成本信息，别堆仓库概述。
  边界：统计功效低，三次重复不能补足任务多样性；selective 的语料并不完全匹配，
  不能得出“AGENTS.md 无效”或“选择性加载总有效”的结论。
- **[Harness-IF](https://arxiv.org/pdf/2608.11727v1)**，首次提交 2026-08-12，v1
  （PDF 内页写 July 15，检索窗口按提交历史）。60 个编码任务、12 个模型；
  against-prior 合规准确率比总体低 3.6–7.4 个百分点。
  吸收：新增规则应有去掉该规则的对照、反默认倾向案例，以及多轮用户纠正案例。
  边界：测的是规则遵循，不是开发吞吐；观察到的优先级不改变实际指令层级。

### 4. 长任务、协作与补丁质量

- **[LoopsBench](https://arxiv.org/html/2608.00267v2)**，首次提交 2026-07-31，
  核对 v1 及 2026-08-10 v2。
  112 个任务、8 种语言、9 个领域；最佳配置完整解决率 25.00%。
  保留已完成节点的回归义务，按有证据的前置依赖选择下一单元；记录恢复后的
  剩余任务。边界：这是基准暴露的缺陷，不是上述流程必然提升的因果证明；
  DAG 不完整，公开任务有污染可能，测试通过不是全部语义正确。
- **[When Agents Coordinate](https://arxiv.org/html/2608.16801v1)**，
  2026-08-17，v1；§3、§6、§9。1,902 次主实验及 244 次封存复查，合成 Python 任务。
  八 agent 的消息密集任务使用共享文件少用约 42% 输出 token，链式任务却可能增加开销。
  吸收：同一材料多次发送时用单一制品加引用，交接围绕相邻依赖，计入协调成本。
  边界：不是总美元成本下降 42%；单靠 coordinator 标签没有可靠成功收益，
  原实验存在查找隐藏评分材料的行为，需看封存复查而非受污染的优势。
- **[TRIM](https://arxiv.org/abs/2607.18161v1)**，2026-07-20，v1。
  报告跨 scaffold 减少 17.9–32.9% 功能冗余，验证成本约为 Delta Debugging 的一半。
  保留已有的成功后轨迹辅助精简；只动本任务所有的改动，预算不足或验收薄弱时跳过。
  边界：研究的 CodeSlop 指标不是全部代码质量；更少行数本身不是改进。

### 5. 九月初补充核查

- **[Harness-of-Harness](https://arxiv.org/html/2609.01481v1)**，2026-09-01，v1；
  表 2–3、附录 B.2/B.5/B.7。三组模型-harness 的系统实验及消融支持证据反馈、
  动态计划和从已有制品继续开发。45 个 GameCraft 任务上，同为三轮，得分
  71.52 对 58.24，但 token 8.41M 对 6.33M；两轮 HoH 为 64.84/5.67M。
  吸收：基于新证据修订计划，复用已验证制品，分离开发测试和最终评估。
  边界：同轮数不等于同 token；每个任务/条件只有一个有效运行，传输故障被替换，
  不能将摘要的相对评分提升解释为等成本成功率提升。完整三角色运行框架不作默认。
- **[HarnessDev](https://arxiv.org/html/2609.01437v1)**，2026-09-01，v1；§4.2–4.3。
  六个创建模型、四域、五基准共 2,207 个不同下游实例。自动生成 harness 在编码和
  搜索研究上仍落后成熟参考系统；改进在换 executor 或 held-out 任务上不稳定。
  支持保留成熟宿主、以实际 executor 验证转移，而非按模型品牌分配能力。
  边界：这些基准差异不证明所有自演化方案失败；自测试次数与分数的相关性也不是因果。

## 保留为实验的机制

| 一手来源 / 日期 / 版本 | 证据与决定 |
| --- | --- |
| [SKILL.state](https://arxiv.org/html/2608.26263v3)，08-26 首发，09-02 v3 | 有合成环境和 InterCode/τ-bench 对照，CTF 54.2% 对最强基线 46.4%。可借鉴显式状态；丢弃全部历史要求状态是充分统计量，开放式开发常不满足。保留原始证据和最近工具对，禁止由 skill 擅自清空宿主上下文。作者页面称 accepted at EMNLP，本次未独立核验会议录。 |
| [Optimal Skill Selection / BPS](https://arxiv.org/abs/2608.19993v1)，08-20 | 理论依赖收益模型和上下文惩罚假设；一个改造 BigCodeBench 上的结果不足以替换通用路由。采用边际覆盖与 token 成本意识；算法、打分器及数值阈值保持实验状态。 |
| [Prime Agent](https://arxiv.org/abs/2608.23552v1)，08-24 | 发布完整 RLM/harness 系统并报告跨任务收益。不能把系统、工具、搜索预算的联合结果归因于 skill 文本；不默认引入递归子代理、常驻 daemon 或框架迁移。 |
| [TRUSS](https://arxiv.org/abs/2608.17588v1)，08-18 | 有静态检查与 shadow execution 的联合评测；吸收“语法有效不代表行为有效”。报告的 100% 指特定基准指标，修复后的攻击成功率仍非零，不作普遍安全保证或额外审批来源。 |
| [The Scaffolding Matters More Than the Interface](https://arxiv.org/abs/2608.08654v1)，08-09 | 七个 scaffold、五个模型，但仅一个软件任务；作为工具面比较的补充线索，不推广其优劣排序。 |
| [A Phased Workflow](https://arxiv.org/abs/2608.30701v1)，08-31 | 行业经验报告，明确缺少工作流效能指标。可作背景，不据此要求所有任务先做多阶段人工审批。 |
| [AgentFactory](https://arxiv.org/abs/2609.01045v1)，09-01 | 八基准五领域，联合模型微调和工作流搜索；仅作训练/系统优化候选，不能把联合增益归因于自然语言 skill 改写。 |
| [Scientific Agent Skills](https://arxiv.org/abs/2609.00065v2)，08-30 首发，09-02 v2 | 163 个技能的语料/文档测量；作者明确无任务级评测与宿主选择率。作为渐进加载的工程资料，不计入效能提升的实验证据。 |

## 日期异常与历史依据

[The Scaffold Effect](https://arxiv.org/abs/2607.22585v1) 的编号为 2607，
提交历史却显示 2026-06-08；保守列为窗口外/日期异常背景，不计入近期证据。
同理，不用搜索引擎的“几周前”、论文编号或会议召开日冒充首次发表日期。
旧版已吸收的 SkillsBench、Evaluating AGENTS.md、ContextBench 等继续作为
历史来源，见 `source-map.md`，不重新包装成最近两个月的新发现。

## 本次实现与验证边界

实现映射：工具/检索开销 → `efficient-execution.md`；诊断和选择性验证 →
`skill-context-harness-governance.md`；统计与成本口径 → `agent-evaluation-standard.md`；
依赖/恢复 → `loop-auto-mode.md`；技能复用 → 治理与 data-flywheel；
能力路由 → `model-capability-profiles.md` 和工作流选择器。

本版本是**有研究依据的工程改写**。静态检查、路由测试及行为 smoke 能证明对应
局部性质，不能证明跨 Codex、Claude Code、Copilot、OpenHands 等全面提升。
默认推广的量化收益仍需要这些模型-harness 上独立、配对、多任务的 held-out 评测。
用户要求安装本次更新与“已证明可迁移”是两件事；可执行授权更新，同时如实标注证据状态。
